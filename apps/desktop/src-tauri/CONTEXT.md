# apps/desktop/src-tauri/

Rust crate `typefaced-desktop`: the Tauri 2 shell, layer `driver`. It registers the
typed IPC commands and serves the frontend from `../dist`. Up: [apps/desktop/CONTEXT.md](../CONTEXT.md).

| File | What it does |
|---|---|
| `Cargo.toml` | Crate manifest: lib `desktop_lib`, depends on `tauri`, `tauri-specta`, `specta`, `tf-commands`, `tf-ai-host`; dev-dependencies: the TypeScript exporter (used by the `export_bindings` test), `tauri` with its `test` feature and `serde_json` (the IPC permission test); the optional `bench` feature (dev-only benchmarks) adds `serde` and `serde_json` |
| `build.rs` | Runs tauri-build with an app manifest listing every app command (`APP_COMMANDS`), so Tauri checks app commands against the capabilities; tauri-build writes their `allow-`/`deny-` permissions to `permissions/autogenerated/`. On Windows MSVC it embeds `windows-app-manifest.xml` through the linker for every binary, so `cargo test` executables start (tauri-apps/tauri#13419) |
| `windows-app-manifest.xml` | Windows manifest that selects Common Controls v6 |
| `tauri.conf.json` | Tauri config: product name, version, identifier `com.typefaced.desktop`, dev URL, 1280×800 window, strict CSP (allows WebAssembly), bundle icons |
| `capabilities/default.json` | Tauri capability for the `main` window only: `core:default` plus `allow-<command>` for every app command (`app_info`, the `ai_*` commands, the dev-only `bench_*` commands). Other windows and remote URLs can call none of them. (No `CONTEXT.md` in that folder: Tauri reads every file there.) |
| `.gitignore` | Ignores `target/`, the generated `gen/schemas` and the generated `permissions/autogenerated` |

| Subfolder | Context |
|---|---|

| `capabilities/` | See `default.json` above |
